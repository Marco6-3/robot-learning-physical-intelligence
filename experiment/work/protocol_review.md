# GRU / Mamba 稀疏事件假设：冻结前方法审查

本文是针对用户已提供实验方向的方法审查建议，不把尚未执行的检查写成结果，也不宣称已经完成预注册。正式运行前，应由执行脚本生成不可变配置、数据清单、拆分索引、代码版本与 SHA-256，并明确哪次运行属于调试、探索或确认。

## 执行方具体模拟方案审查

执行方提出的固定方案为：20 Hz、每记录 128 步，观测独立随机正负符号 k[t] 和查询门 q[t] 以及高斯干扰通道；y[t] = q[t] AND (k[t−lag] > 0)；只评分 t≥64，lag 为 2 或 64，即 0.1 s / 3.2 s。训练集 64 / 256 条嵌套记录，验证 256、测试 512，5 个配对数据与初始化种子，固定 400 次更新、批量 16，每模型相同的两个学习率候选。该方案可以冻结为“算法性因果延迟读取”实验，允许零结果，不需要为符合预期结果更换生成器。

冻结前最小修改 / 声明如下：

- q 的概率为 0.02 / 0.2 时，阳性帧比例约为 1% / 10%；若用 0.4，较密条件约为 20%，不能写成 10%。用同一 uniform 随机数组在不同阈值处截断，获得配对稀疏度条件。
- 加入 score=q 的无记忆确定性基线：它在全时间线的 AP 约为 0.5，即使真实阳性比例只有 1%。必须同时报告 q=1 的查询子集 AP，其无记忆参考值约 0.5。不能把全帧 AP 从 0.01 到 0.5 解释为学会了历史。
- 加入 oracle=q*(k[t−lag]>0)，应得 AP=1；这个检查验证对齐、打分与生成器规则，不代表训练模型性能。
- lag=64 要求保存 64 个独立 bit 的延迟队列，既增加时间距离，也增加信息容量需求。该任务不等价于保持一个二元接触潜状态 3.2 s。结论必须命名为延迟读取，不推广到所有长记忆或物理接触过程。
- 主指标可以定义为查询子集 AP，完整时间线 AP 与 Event-F1 等为辅助；若坚持全时间线 AP 为主，也必须要求查询子集诊断支持记忆学习。此选择需要在正式结果前写入配置。
- q=1 子集是根据当时可见输入定义的预设子群，因此可以用于诊断；它不能代替完整流中的误报、漏报、事件率和时长报告。
- y=1 是单步事件。需要预先确定相邻阳性帧算多个点事件还是合并成事件区间；较密条件相邻阳性更多，匹配规则不能随稀疏度改变。帧级 AP 最适合作为此合成任务的主要结果，事件检测指标只作为已声明规则下的补充。
- 5 个种子若同时改变训练 / 测试数据与初始化，应命名为 5 个独立生成数据的配对重复。先在每个重复内按测试记录配对重采样，再对重复重采样。不要称为固定数据上的纯初始化稳定性实验。
- 只用 64 / 256 两个训练规模仍能定义三重差分，但不能声称获得完整学习曲线，或稳定估计达到目标性能所需样本量；主表可称小 / 大数据预算结果。
- 两个学习率候选应使用独立 pilot 数据与验证集，选择规则和适用条件提前确定。正式种子不可凭测试表现重选学习率。
- 400 次更新是训练资源预算，不自动代表所有模型收敛。报告验证曲线；如多数模型仍持续改善，应把结果限定为该训练预算。不能只为落后模型追加训练后继续称为原确认性比较。

若需要额外检验“单个潜状态保持”而不是延迟队列，可另立未查看结果的补充协议：每条轨迹在随机早期时刻呈现一个随机状态位，状态此后保持；短记忆条件重复呈现该状态位，长记忆条件保持静默，后期查询门与状态位共同决定标签。这个方案降低信息容量需求，但也引入提示重复次数差异，应当被视作互补机制而不是无条件更优的替代。当前有限研究可先完成延迟读取方案，并诚实限制推论。

## 1. 要检验的命题与证据边界

- **H1**：约 1% 稀疏事件、约 100 ms 有效记忆、有限训练数据时，GRU 的样本效率优于参数量匹配的 Mamba。
- **H2**：保持稀疏度和任务规则不变，把有效记忆延长到 2–5 s，Mamba 相对 GRU 的表现改善。相对改善不等于 Mamba 必须绝对超过 GRU。
- **H3**：架构差异受稀疏度、记忆长度、训练数据量的联合影响。要检验三因素交互，必须有非稀疏对照、至少两个记忆水平、至少两个数据量水平。

模拟实验只能支持所生成过程内的命题；真实触觉独立标签实验才能提供对应数据域的外部证据。离线预测优势不能证明接触闭环控制优势。应接受支持、反驳和证据不足三种结论，不能以找到显著结果为停止条件。

## 2. 最小可判定的因子设计

建议确认性设计固定稀疏度为 1% / 10%，有效记忆为 100 ms / 3 s，训练数据量为小 / 中 / 大三个预先固定的独立轨迹数量。模型至少包括 GRU、Mamba 和一个局部 MLP 或短感受野 TCN；资源允许时同时包含 MLP 和 TCN。不能用 Transformer 替换 Mamba。

所有条件必须明确以下单位：

1. 采样率与物理时间，例如 50 Hz 下 100 ms 为 5 步，3 s 为 150 步。不能只更改“秒”的说明而沿用相同步长。
2. “1%”究竟是事件起始点占比、事件占据帧占比，还是查询机会中的阳性比例。这三者不同，必须报告实际值、事件数和总时长。
3. 有效记忆是预测确实需要的历史信息距离，不是输入序列的长度。短 / 长两条件应给予相同的完整输入长度，长度必须覆盖最长所需历史；仅改变关键线索位置或需要保持的潜状态时间。
4. 小 / 中 / 大必须是嵌套训练轨迹子集，不能是高度重叠窗口数。验证集与测试集大小固定，不能随训练规模改变。

CPU 时间不足时，可以在查看模型排名前统一降低参数预算、采样率或候选数，并重新冻结配置。不能仅为一个架构减少训练量，也不能删除 H3 必需的因子后继续宣称验证 H3。

## 3. 模拟过程必须先通过的审计

### 3.1 稀疏与可预测必须分开

独立于所有可见历史的随机事件没有可学习的先兆。不能把模型对不可预测随机触发的失败解释为记忆能力差。短 / 长记忆条件保持相同标签函数、噪声分布、事件率、传感维度和条件可预测性，只改变必要历史距离。

一种可审计的诊断生成器是：可见历史包含独立随机符号流，当前查询与过去指定位置的符号共同决定事件；一个可见、与符号独立的查询门控制事件出现频率。通过对称符号分布确保只看当前符号不能推知标签。该过程检验的是延迟信息保存，不等于真实接触动力学；最好另外保留一个潜状态保持 / 切换过程，避免只证明某一种人工延迟题偏爱某架构。

若使用可见查询门，必须同时报告完整时间线的指标和查询机会内的指标。查询门本身会提高完整时间线 AUPRC，但不应被误认为模型学会了记忆。门的出现频率改变事件密度，也可能改变学习难度，因此所有模型差异应先在同一因子条件内比较。

### 3.2 防止捷径

- 事件不能在固定绝对时刻、固定窗口末尾或固定记录编号规律中出现。
- 测试序列的背景、噪声、随机种子、初始状态和轨迹必须独立于训练集。
- 正例与困难负例应共享当前时刻的边缘分布；不能让正例独有脉冲、幅度或文件长度。
- 不输入生成器的隐藏状态、未来控制、未来接触力，除非这些信号本来就是部署时可用输入。
- 标签中的记忆关系不能被当前观测直接复制。对仅当前输入与局部窗口基线的强表现应先作捷径检查。
- 用已知生成规则构造因果 oracle，并检查其预测显著高于常数基线，证明任务可解；用打乱历史和截断历史检查长记忆信息确实必要。
- 先验证时间索引与依赖关系，再运行正式模型。训练 loss 下降本身不证明任务或拆分正确。

不要根据正式测试的 GRU / Mamba 排名反复调整噪声、滞后或标签函数。生成器调试必须使用单独的数据种子，任何结果知情后的修改都属于新协议。

## 4. 检测与提前预测分开冻结

**检测任务**：在时间 t，输入仅含 x[≤t]，目标为当前接触事件或状态 y[t]。若事件已经在当前触觉输入中可见，应称为检测。

**预测任务**：在时间 t，输入仅含 x[≤t]，目标是 t+h 时刻事件或预先声明未来区间内的事件，h 严格大于零。需要明确最小提前量、区间宽度与接触时刻标签误差，h 不应小于对齐误差后仍宣称提前预测。

不能在使用当前帧阈值派生标签后声称预测未知未来事件；不能使用双向网络、居中滑动均值、向前回填、全序列归一化，或用测试事件对齐窗口。跨切分边界的滤波、重采样及滑窗也会泄漏。

检测与预测可共享因果编码器，但应分别报告，不能在看到结果后选择更好的一项作为主任务。

## 5. Mamba 的 Windows / CPU 实现真实性

允许使用纯 PyTorch 的 Mamba-1 参考扫描来实现数值等价的训练，不要求一定运行 CUDA 融合核。必须准确说明它是参考实现，不用其运行速度代表官方融合实现的速度。

需要保留 Mamba-1 的输入投影、因果深度卷积、SiLU 激活、由输入产生的 Δ / B / C、负实数 A 参数化、D 跳连、SiLU 门控与输出投影，并保留官方关于 Δ、A、D 的初始化及优化处理。仅给普通线性 SSM 改名 Mamba 不合格。

官方参考递推为 h[t] = exp(Δ[t] A) h[t−1] + Δ[t] B[t] u[t]，随后以 C[t] 读出并应用 D 与门控。该简述只覆盖扫描核心；完整模型仍需要前述组件。官方来源：[Mamba-1 模块](https://github.com/state-spaces/mamba/blob/main/mamba_ssm/modules/mamba_simple.py)、[selective_scan_ref](https://github.com/state-spaces/mamba/blob/main/mamba_ssm/ops/selective_scan_interface.py)。运行时应固定具体提交，不能只记录会变化的 main。

正式训练前，在小张量上验证本地扫描与独立按官方公式编写的参考扫描前向值和参数梯度一致；检查未来输入扰动不会改变过去输出，且改变当前输入确实改变 Δ / B / C。若可访问官方融合核，另作前向 / 梯度对齐。若只有同一份代码的自比较，应明确不构成独立实现验证。

## 6. 公平训练控制

- 选择统一参数预算，例如约 20k–50k，模型总可训练参数差异建议不超过 5%，并逐个记录真实参数量。不能按有效利用的参数数手工排除某架构成本。
- 所有模型使用相同原始输入、相同训练轨迹、相同标签权重、相同批次构造与归一化。预处理参数只在训练集拟合。
- 参数匹配不等于计算匹配。主分析应明确是相同数据暴露与训练更新预算下比较，同时记录时间和优化状态。CPU 参考实现耗时不适合当作架构效率结论。
- 每个架构应有相同验证搜索预算，例如同一数量学习率候选和最大更新次数；候选可基于架构惯例预先设置，不能只认真调 GRU。所有候选和失败运行都保留。
- 每个种子用验证集选择 checkpoint 与阈值。训练停止规则在运行前固定，不查看测试分数早停。
- 使用完整反向传播覆盖最长目标依赖；若截断反传小于 3 s，就无法公平检验 3 s 学习。状态不能跨独立轨迹继承。
- 局部 MLP / TCN 用于验证局部线索是否足够，其短感受野是显式实验条件。若把 TCN 纳入“最佳序列架构”比较，还需一个感受野覆盖最长历史的版本，不能借刻意短窗口削弱它。
- 训练集稀有事件不足时应如实列出数量。可以采用预先固定的类权重或采样规则，但不能令不同模型看见不同正例数。测试集保持原始事件比例。

## 7. 数据拆分与真实数据准入

FlexiTac 是优先考察对象，不预先假定它含适用的独立事件标签。正式使用前应记录来源、版本、许可、采样率、同步误差、记录结构和标签产生方式。

真实数据主任务需要独立于目标触觉输入构造的事件依据，例如同步外部力传感器、运动捕捉、视觉标注或实验接触开关。若接触标签只是把输入触觉通道本身阈值化，这最多是信号规则模仿，不应当作独立物理验证。

先按对象 / 被试 / 完整实验轨迹分组拆分，再切窗口；任何窗口重叠、同次接触、同一来源文件不得跨训练验证测试。对于同一对象多次录制，应选择符合泛化目标的最高层级分组，并明确测试的是新记录还是新对象。训练样本量使用完整独立轨迹数，同时给出帧数、事件数和时长。

真实数据不能仅凭截取较长输入窗口宣称具有 3 s 有效记忆。需要预先定义的历史截断检验或独立实验过程依据。若数据不支持稀疏 / 记忆因子操控，可作为外部检测验证，不能代替完整 H3。

## 8. 指标与阈值

1. 主指标建议使用时间步级 average precision（AP），明确实现和它与梯形积分 PR-AUC 的差别，不混用名称。报告事件率对应的无信息参考值；不同稀疏率下 AP 的绝对值不能直接作为架构优劣证据。
2. Event-F1 对预测事件与真实事件进行一对一匹配，匹配窗口、合并相邻警报的规则、不应期和时序方向在运行前固定。一个真实事件最多贡献一次 TP，多余警报依规则作为误报。
3. onset latency 报告已匹配事件的中位数与分位数，并同时报告漏检率。只报检测成功事件的平均延迟会掩盖漏检。
4. false alarms/min 明确分母是完整评估时长还是非事件时长，建议主报告为完整评估时长；不能只保留事件中心窗口。
5. 验证集选定阈值后固定测试，例如验证 Event-F1 最大阈值，或验证误报率不高于预设上限时的最高召回阈值。全模型使用同一选取准则。不能在测试 PR 曲线上挑每个模型最有利阈值。

测试集中实际正例 / 事件数必须足以估计指标；bootstrap 某次抽样没有阳性时应报告处理方式和发生比例，不能静默丢弃导致偏差。

## 9. 统计量、种子与停止规则

建议至少 5 个固定训练种子；若目标是“强支持”，优先一次预先计划 10 个，不根据前 5 个的显著性决定是否添加。训练种子、数据生成种子和独立测试轨迹分别记录。相同条件下模型共享数据与拆分，尽量配对初始化运行编号，但不能把共享测试集的多个种子当成多个独立数据集。

定义 D(s,m,n) = AP_GRU − AP_Mamba，其中 s 为稀疏度、m 为必要记忆、n 为训练规模。预先指定一个最小有意义差异 ε，例如 AP 的 0.03 绝对差；ε 的取值应在结果前冻结，不能事后根据置信区间改变。

- H1：D(稀疏,短,小) > ε；样本效率还应报告完整学习曲线，或预先指定小 / 中训练规模的 log 样本量曲线面积，不能只靠一个任意训练规模定义效率。
- H2：D(稀疏,长,n) − D(稀疏,短,n) < −ε。n 或跨哪些 n 求平均必须预先固定。若结果仅从 GRU 大胜变为小胜，也符合“相对改善”，但不支持“Mamba 已胜出”。
- H3：明确三重差分 C = {[D(稀疏,长,小)−D(稀疏,短,小)]−[D(较密,长,小)−D(较密,短,小)]} − {[D(稀疏,长,大)−D(稀疏,短,大)]−[D(较密,长,大)−D(较密,短,大)]}。只有 C 的不确定性区间支持非零，才有该三因素交互的直接证据。若没有预先声明方向，H3 应采用双侧判断；不能从任意两条件交叉排名推出三重交互。

对每个测试记录保留全长预测。以最高独立来源层级（对象 / 被试 / 轨迹）进行配对 cluster bootstrap，相同重采样索引应用到所有模型和相关因子条件，然后重算 AP 与差分；不能逐帧独立 bootstrap。进一步对训练种子配对重采样，呈现数据抽样和训练不稳定性的共同影响。应明确这是对当前数据设计的条件性推断。

H1、H2、H3 为一个事先定义的主要检验家族，可用 Holm 校正；或提前固定同时置信区间方法。其余模型、预测时距和事件指标作为预设辅助结果完整展示。无需把所有辅助结果都说成独立“证明”。

**停止规则**：固定确认性矩阵完成并通过实现 / 泄漏审计后停止该轮，不论结果支持与否。强支持至少需要预设主要效果达到有意义阈值、校正后的不确定性支持方向、多个种子一致、局部基线与 oracle 诊断正常，并由独立真实数据方向一致的证据补充。缺少真实标签、运行不足、效果小或区间跨零时结论为边界明确的部分支持 / 证据不足；不继续更换数据和超参直到“证明”。新设计需要新版本、说明变更缘由并使用新的未触碰测试数据。

## 10. 最终应保留的可复核产物

冻结配置与哈希；数据版本 / 许可 / 清单；分组拆分索引；生成器与模型源代码；环境版本；各条件参数量；全体调参和失败记录；每种子训练日志；验证选取的 checkpoint / 阈值；完整逐记录预测与标签；事件匹配详情；bootstrap 脚本；主 / 辅指标表及带不确定性的学习曲线；支持、反驳、未完成部分分别陈述的中文报告。
